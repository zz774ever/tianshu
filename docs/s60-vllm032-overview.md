# S60 / vLLM 0.32 适配与验证总说明

## 1. 文档目的与总体结论

本文汇总 Enflame S60 上 vLLM 0.32 的适配工作、真实验证结果、已知限制和交付记录，作为本仓库的总览入口。本文依据已有日志和结果编写，不代表重新运行实验，也不构成完整发布认证。

**总体结论：适配与记录交付已在用户授权范围内完成，但不是全部验收项通过。**

- Qwen3-0.6B 已有 offline eager、Graph、TP2、在线服务及 NVIDIA 逐 token 对比证据；严格精度对齐未通过，用户接受已披露差异。
- Qwen3.6-27B / 35B-A3B 的 TP2 eager 与 Graph 四组正式请求共 **103/104** 通过。35B eager 的一个单文本断言失败，用户明确接受该特定例外；原始结果仍是 FAIL。
- Harbor 拉取及依赖它的镜像构建按用户授权跳过；镜像发布和 runner CI 未验证，不能视为发布就绪。
- 记录已归档到本仓库，并保留成功、失败及诊断证据，不将诊断结果替换正式验收结果。

## 3. 主要完成工作

### 3.1 环境与插件适配

- 对齐官方 vLLM 0.32 基线，执行依赖、插件导入、编译器与设备检查。
- 保留厂商 PyTorch、FlagTree、FlagGems 依赖栈；插件安装使用 `--no-build-isolation --no-deps`，避免意外替换运行时。
- 更新 Dockerfile 与构建入口的版本默认值，并补充参数转发及版本回归检查。

### 3.2 算子、编译与分布式兼容

- 修正 GCU Inductor 整数指针类型处理，避免全局 int64→int32 源码替换破坏地址计算，并区分相关编译缓存。
- 采用厂商作用域 Triton 词表 mask 实现，保留上游 int64 输出契约，覆盖 int32/int64 输入及边界情况。
- 修正 softmax MoE 路由 FL 分发与 padding，补齐专家 ID 为 `-1` 的契约，避免调用 CUDA-only 路径。
- 通过注册的 collective custom-op 边界处理 FlagCX Graph 编译，避免 Dynamo 追踪 Python stream 操作。
- 对已确认的特定 BF16 linker 候选失败使用现有 autotuner 异常机制；未知错误或全部候选失败仍然报错。
- 验证显式启用 FL `SiluAndMul` 的配置，完成相应 35B Graph 请求验证。

## 4. 验证结果与验收边界

### 4.1 功能验证矩阵

| 模型 / 检查 | 观察结果 | 结论与边界 |
| --- | --- | --- |
| 0.6B offline eager | 已有实际生成记录 | 基本功能有证据，不代表其他模型通过 |
| 0.6B TP2 | 完成真实 FlagCX collective 验证 | 仅覆盖已测环境与配置 |
| 0.6B eager / Graph 对比 | 指定配置下，5 个提示各 32 token，共 160/160 一致 | 是同硬件执行模式对比，不是 NVIDIA 精度验收 |
| 0.6B 在线服务 | eager / Graph 的 HTTP 并发、流式验证已有记录 | 不外推到未测模型和部署环境 |
| 27B TP2 eager | 26/26 请求通过 | 正式请求组通过 |
| 27B TP2 Graph | 26/26 请求通过，FULL decode capture 35/35 shapes | 正式请求组通过 |
| 35B-A3B TP2 eager | 25/26 请求通过 | 原始单文本断言 FAIL，用户接受特定例外 |
| 35B-A3B TP2 Graph | 26/26 请求通过，FULL decode capture 35/35 shapes | 正式请求组通过 |
| 27B / 35B 四组汇总 | 103/104 请求通过 | 不能改写成 104/104 或全部后端验收通过 |

35B eager 失败回答缺少断言要求的字面词 `limitations`，未建立硬件根因。后续两个相同请求并发提交时通过原检查，只能作为执行上下文敏感性的诊断证据，不能替代原单请求验收。

### 4.2 NVIDIA 精度对比

0.6B 使用官方 NVIDIA vLLM 0.32.0 参考输出，模型文件经过 SHA256 一致性核验，采用 greedy 逐 token 对比。严格对齐未通过；原始对比中，算术提示首次在第 7 个 token 分歧、代码提示首次在第 13 个 token 分歧，另三个提示完整匹配 32 token。

后续归一化与输出 head 诊断改变了部分分歧位置；FP32 head 在原五个提示上匹配，但新增十个提示仅八个匹配。它们不是原 BF16 配置严格通过的证据。用户接受已披露数值差异并结束进一步精度调试，该接受也不等于其他模型已完成 NVIDIA 精度验证。

**27B / 35B 尚无足够证据声称完成独立 offline 全套验证或 NVIDIA 逐 token 验收。**

### 4.3 回归测试与 CI

最终聚焦回归记录为 **115 passed**，构建入口回归为 **7 passed**。这些是已有日志中的观察结果，本次文档整理没有重新运行测试。历史完整单测收集曾遇到可选依赖 `torch_npu` 缺失，不能把聚焦通过表述为整个测试套件通过。

Harbor 基础镜像拉取受仓库授权限制。用户明确授权跳过该拉取及依赖它的构建，状态为 **SKIPPED**，不是 PASS。镜像发布与 runner CI 未验证，后端 CI 保持禁用。

## 5. 使用前提与关键配置

以下配置仅说明已测路径的必要条件，不是未经验证环境中的一键部署保证。完整操作以[版本使用说明](../records/s60-vllm032/usage/enflame-vllm032.md)为准。

编译模式精度仿真配置：

```bash
export TORCHINDUCTOR_EMULATE_PRECISION_CASTS=1
```

已测 S60 Qwen3.6 配置显式选择 FL SiLU：

```json
{"custom_ops": ["none", "+SiluAndMul"]}
```

此 JSON 是 compilation configuration 的内容；离线参数与服务 CLI 的传递方式不同，应按具体入口设置。`SiluAndMul` 大小写必须保持；`+silu_and_mul` 不会启用同一注册类。精度仿真是环境选项，不是插件自动安装的生产默认值；新部署应单独确认。编译成功、健康检查 HTTP 200 或服务启动，都不能单独证明输出正确。
